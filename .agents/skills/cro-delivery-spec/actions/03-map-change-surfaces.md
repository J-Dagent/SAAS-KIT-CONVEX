# 03-map-change-surfaces

## Purpose

Map the approved change to web, form, tracking, integration, backend and external-system surfaces.

## Inputs

- ready decisions
- repo evidence

## Process

1. Map each approved change to code/runtime surfaces.
2. Identify dependencies and risk.
3. Mark form work for implement-forms.
4. Keep architecture detail at requirement level, not code level.

## Outputs

- change-surface map
- risk
- dependencies

## Test

Moving a hero form must include form/data surfaces without turning the spec into implementation code.

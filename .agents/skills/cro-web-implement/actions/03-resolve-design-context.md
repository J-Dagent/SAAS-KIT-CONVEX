# 03-resolve-design-context

## Purpose

Apply DESIGN.md when present or existing design-system conventions when absent.

## Inputs

- repo
- design context

## Process

1. Read DESIGN.md if present.
2. Otherwise use existing project tokens/components.
3. Record constraints that affect implementation.
4. Do not touch strict data contracts.

## Outputs

- visual constraints

## Test

Do not require Open Design runtime just because DESIGN.md is referenced.
